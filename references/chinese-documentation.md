# 中文变量注释与ST解释

用户需要能在PLC工程里直接阅读说明，不能仅把说明放在外部文档。以中文注释为默认交付约定；已有项目明确使用其它语言时遵从项目约定。

- 全局变量、程序局部变量、外部变量、FB输入/输出/内部变量、结构体成员都要写实际用途。数值注明单位、有效范围、特殊无效值；BOOL说明TRUE代表什么、是电平还是脉冲；数组说明槽位与设备的对应关系。
- 对命令、反馈、状态、参数、临时变量作准确区分。握手确认注明确认的阶段，例如“本地库已接管”，不能简化为“服务器已收到”。保持变量说明何时重置，不能与一般复位混淆。
- 同名变量可能在不同POU含义不同。采用所属POU加变量名作为必要的区分依据，不能把全部Count注释成动作次数、把全部Position注释成轴位置。
- ST按“大段 → 小段 → 语句”排版：大段用独占一行的 `// ===== 功能 =====` 标题，前后留空行；小段用独占一行的 `//` 说明目的。复位、状态切换、启动/结束条件、队列所有权、超时/故障、协议边界等重要逻辑单独说明。简单赋值、计数、单位换算、数组复制在该行末尾写简短 `//` 注释；不为每个 `END_IF`、`ELSE` 和多行调用参数重复添加前置说明。
- 注释必须对应实际表达式，尤其NOT、比较边界、故障/超时/重试。不要在任意IF上重复“检查条件”，不要把“填无效值”注释成“计算平均值”。常量和字节序应解释协议含义；循环、步骤切换、首扫描初始化说明具体目的。
- 初始化与重载应说明谁发请求、谁确认、哪些条件允许应用、完成后谁撤销。首次扫描发起请求与跨扫描完成初始化分开解释；不能只写“初始化变量”。
- 分包发送的段落注释用现场人员能区分的动作写法：包满即排队发送、正常结束发送不足一包的尾包、重载等待旧队列发送后切换配置、复位若选择丢弃须明确写出丢弃范围。避免“暂停排空”“复位排空”这类没有说明何时停采/何时清队列的短语。
- 按项目要求控制条件嵌套深度，具体层数留在项目约定。简化时可提取有意义的条件变量、使用互斥分支或状态；保留分支选择时刻、赋值顺序及每周期调用次数。不可机械拆成多个IF，使前一赋值又触发后面的分支；除法、数组索引等操作仍需在有效范围检查之后执行。
- 批量补注释后人工抽查初始化、正常路径、异常、边界与复位；通过词法比较确认去除注释后的可执行代码未改变。若同时改变了逻辑，不能用注释等价检查代替功能回归。
- IEC 61131-10 XML的变量注释应实际写入变量/成员的Documentation，使用匹配官方XSD的TextBase派生类型与元素顺序；源文件中的行尾注释不一定被转换器带入变量表。检查完整XML，尚未在Sysmac确认显示时如实说明。
- 注释版导入补丁应包含所有实际新增注释的POU和类型。提示同名对象覆盖会替换该对象的正文；用户已经手工改动的程序先比较。原现场I/O、组态、保持属性和用户参数不能因补注释被重置。

真实轴、I/O和工艺触发的映射不能由变量名猜测。若模板中有被注释的轴表、随机值或测试信号，它们只是待核对候选项；交付要明确“当前未绑定”并给出映射表。实际绑定前，监测默认关闭；不能把候选映射变为可执行代码。

采集触发必须说明是单扫描脉冲还是整段动作保持的窗口，以及结束扫描是否采样。只有启动脉冲时，在工艺程序中形成保持窗口，定义完成、取消、故障和复位的释放条件；不要把工艺步序塞进通用采集FB。需要最后到位点时，应检查调用顺序，让该点被采入后再关闭窗口。采集槽号、轴编号和EtherCAT节点号分别说明；轴引用使用模板已注册的变量，并匹配全局/外部声明的类型和属性。

运行 `python scripts/check_chinese_comments.py delivered.xml` 检查变量/成员的中文Documentation、ST分段标题和注释风格。这只是格式覆盖检查，不能验证中文解释、现场映射或编译结果正确，不能代替原生导入和人工抽查。
