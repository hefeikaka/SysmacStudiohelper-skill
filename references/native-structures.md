# 优先复用厂商系统结构与既有设备结构

## 先找结构，再设计引脚

生成设备适配或采集FB前，先检查模板工程和匹配版本手册中已有的轴、设备、网络诊断、命令、配方结构。已有对象包含所需数据时，优先传入该对象的原生类型或引用，由FB内部读取成员；不要让调用者把每个成员拆成标量后重新接回FB，也不要仅为改名复制一套相同结构。

区分设备数据接口与路由/控制接口。设备身份尽量由一个结构引用表达；槽号、采集触发和许可等确有独立语义的参数可由项目框架管理，不为了“一根引脚”隐藏未经定义的绑定、用物理轴号猜采集槽，或改变触发语义。具体调用形式由目标平台及现有框架决定。

## 建立成员语义对应表

每个需求字段记录：原生成员或已有业务成员、手册/模板来源、类型与单位、更新时间、可用的轴/设备类型、是否需要换算，以及未覆盖的含义。按以下顺序处理：

1. 同含义同单位：直接使用已有成员。
2. 含义相同但表示不同：在FB内部作明确转换、范围检查或枚举映射。
3. 结构中没有同义成员：继续查现有运动指令参数、设备封装或配方结构，只补真正缺失的信息。
4. 仍未确定：明确缺口，不用相似字段名或示例常量冒充真实来源。

禁止将“当前指令值”“最终目标”“速度上限”“反馈值”混为一类。也不能用驱动模式直接替代业务运动方式，或把轴号当业务设备编号。

## 欧姆龙Motion的已确认示例

以W507/W508的标准 `_sAXIS_REF` 为例，版本与支持条件仍需核对：

|成员|真实含义|复用时注意|
|---|---|---|
|Act.Pos、Act.Vel、Act.Trq|实际位置、速度、转矩|转矩为百分比，不能直接当其他量纲的原始INT|
|Cmd.Pos、Cmd.Vel|当前指令位置、当前指令速度|不能自动当最终目标位置、运动设定速度|
|Cmd.AccDec、Cmd.Jerk|当前指令加减速度及跃度|不能拆成两项固定加速/减速设定值|
|Scale.Units|轴显示单位枚举|按接收协议映射，不能直接复制枚举数值|
|Cfg.AxNo、Cfg.NodeAddress|逻辑轴号、节点地址|与业务设备号、采集槽号分开|
|Status、Details、DrvStatus|运动状态、控制详情、驱动状态|保留各自语义；采集意图不等于正在运动|

依据：[W507轴变量说明](https://files.omron.eu/downloads/latest/manual/en/w507_nj_nx-series_cpu_unit_motion_control_users_manual_en.pdf?v=1)、[W508变量与运动指令](https://assets.omron.eu/downloads/manual/en/v2/w508_nx_nj-series_motion_control_instructions_reference_manual_en.pdf)。手册示例不构成所有CPU、固件或用户自定义结构的完整字段表。

## 接口简洁与运行正确分别验证

- 不重建系统结构定义，不创建无硬件绑定的普通结构冒充系统轴。
- 原生结构按目标平台允许的参数方向传递；监测FB不修改轴命令。确认全局/外部声明属性及系统绑定。
- FB内部路由若访问共享存储，记录唯一写入任务；不能从“接口只有一个轴引用”推断FB没有副作用或可以并发调用。
- 延迟处理需要采样时刻快照。必要的报文缓存不属于无意义的结构复制，但只保存实际需要的字段，避免整套轴结构被逐采样搬运。
- 快照的单位/模式等解释信息与数据保持一致；曲线元数据按协议规定时机锁定，不在慢任务读取“当前轴状态”解释历史样本。
- 验证调用接口精简前后数据来源、换算、异常处理与行为；解释器中代用结构/枚举/厂商转换函数的范围明确记录，不能冒充原生验证。
# 单段运动的目标锁存

“只采一段固定运动”不改变原生字段语义。`Axis.Cmd.Pos` 是当前插补指令位置；Flag上升时读它，可能得到起点或中途位置，不能因此命名为最终目标。最终位置/设定速度等来自实际运动指令参数、配方或已核实含有终点的设备命令结构。相对运动须明确绝对终点的计算基准。

在采集触发所在任务保存目标快照，随触发样本交接；采集FB在接受本段开始时锁存，直到该段尾包结束。慢任务事后读取“当前目标”会拿到后续运动参数。若用户需要启动时当前指令值，可作为明确命名的独立字段；不能悄悄替换协议中终点字段。
