# 程序、FB与组态交付

## 从工艺提取规格

提取输入、输出、状态、动作完成条件、超时、互锁、参数、启动/停止/复位、异常恢复及物料处理方式。

先应用用户授权的自动化默认约定与工程上下文，不重复追问常规设备配置。确有冲突、实际绑定未知或恢复动作会改变已知设备行为时才集中澄清。需求、现有工程、用户维护的默认约定依次作为依据。

维护三类信息：用户已确认；工程/手册中已证实；为当前样例采用的假设。不要把“物件消失”等自然语言直接等同于动作完成；需要结合传感器位置和工艺确认。

并行动作分别定义共同启动条件、各自完成条件与循环汇合条件；用户要求同时返回/缩回时，不擅自改成串行。“传感器感应同时伺服到位”通常需确认是两个状态同时成立，还是必须同一扫描出现边沿。运动完成反馈应关联本次命令，避免沿用上一次 Done；测试各设备先后到位的情况。

不把某次试验的200 ms延时、任务周期或整机单件循环当成通用规则。用户已授权的“双到位、双控制气缸”等设备默认按 process-language.md 应用；默认是设计假设，不是现场硬件读取结果。

## 代码与FB

- 按目标型号和版本生成可接受的ST语法、变量定义和调用方式。通用IEC语法或第三方转换器支持不代表目标编译器支持。
- 区分POU定义、变量声明和ST正文。提供手工粘贴版本时，说明变量表与正文的不同位置。
- 生成FB需包含接口、内部变量、实例声明、调用示例和相关测试。普通ST片段不等于已生成可导入FB。
- 明确输出写入者和执行顺序；检查共享输出多处赋值、同一实例重复调用、边沿信号采样和复位优先级。
- 新增 FB 必须功能化：气缸、皮带、伺服定位等各自封装。跨设备步序、流程步骤号、步进条件放在程序段，不能把整机流程封装成一个工艺 FB。设备内部超时、边沿和动作状态可留在设备 FB。现有模板的可复用对象先保留，必要改变需说明。
- 计时方案记录时间基准：若按扫描次数累计，调用周期必须匹配实际任务，并说明漏调、抢占和周期量化影响。使用厂商定时器时，验证声明和调用语义。
- 普通使能撤销、阀输出断电、机械停止及安全停止不能混称。按实际设备行为处理，不从软件输出值推定机械位置。

## 变量与工程组织

按需要交付名称、类型、作用域、初始值、保持属性、用途、发布属性、设备映射和依赖。哪些字段可自动导入、哪些须核对或手工配置，应明确列出。

轴树名称与程序可解析的命名轴变量分别核对。使用命名轴变量时验证变量作用域、类型及轴绑定；使用系统轴引用时从目标 CPU 手册确认支持的数组名称、索引与任务归属，不按界面的 MC1/MC2 标签猜变量前缀。未定义轴引用不可用一个无绑定的普通变量替代。局部修复优先提供仅包含相关 POU 的导入补丁，避免覆盖全局变量和其他程序。

项目树列真实需要的POU和数据类型；任务表列调用程序、周期要求和执行顺序。不要将建议的逻辑分组声称为已在Sysmac中创建的界面节点。

已有工程尽量复用已确认的I/O和任务。需要迁移或改变行为时明确差异，避免破坏既有硬件绑定和库依赖。

## 程序导入与硬件组态分开处理

|通道|适用范围及要求|
|---|---|
|IEC 61131-10 XML|在目标支持范围内导入程序/函数/FB、变量和数据类型；不等于完整硬件工程|
|AutomationML|按目标版本和受支持的电气CAD交换结构处理控制器配置、设备变量等；需要兼容文件证据|
|轴/轴组等专用导入|核对相应功能版本和具体格式，不能与程序XML互换|
|原生工程副本|保留已有组态并经可验证的修改、保存、重开流程交付|

硬件自动化输入通常包括完整CPU型号/版本、模块型号及顺序、网络节点、设备描述文件、通道接线、电气有效状态和驱动接口。已有工程能提供的信息先读取，不重复索取。

若信息不全，可完成逻辑信号表和待映射清单；不要虚构模块或地址。官方有导入入口，只证明软件提供该入口，不证明当前生成器已覆盖全部设备和配置。

用户授权选择离线示例硬件时，可以明确选定真实型号和示例版本，但必须与现场已确认配置分开。区分网络节点、模块位置、逻辑通道和接线端子，不根据通道号猜端子号或内存地址。

生成轴 XML 时，优先读取安装目录内官方格式说明与 XSD；列明文件实际包含的参数、由程序传入的运动参数及仍需任务绑定的部分。虚拟轴和真实驱动器轴分别说明，不能将虚拟轴缩放参数视为真实机械参数。普通流程使能、轴上电、参考位置建立及安全停止分别设计。

跨 AutomationML 与程序 XML 导入时，指定变量由哪个文件首次创建，避免同名设备变量重复定义。提供替代导入版本时写明二选一条件，并核对变量名称、类型和通道链接。基于官方样例修改控制器时也须核对端口名称、固件版本、拓扑、遗留引用；样例来源不等于修改后的文件已经可用。

使用转换工具前确认版本、来源、目标参数和适配样例。不要沿用第三方skill默认的其他PLC品牌参数；不强制依赖特定转换器或本机绝对路径。

生成smc/smc2必须经过真实格式写入及Sysmac打开验证。仅重打包ZIP或改变扩展名不能证明原生工程有效。

## PackML

仅在用户要求时设计或实现PackML，不把普通状态机标为符合PackML。

明确所用状态模型、库和版本，分开机器运行状态、工艺步骤和设备动作状态。按工艺设计停止、保持、暂停、终止、清除及恢复的具体效果；不能机械地把这些命令映射成同一个Enable。

调用方是否继续周期调用设备FB、暂停时如何保存进度、恢复前如何确认位置，应有明确约定。已有项目只需预留接口时，记录预留范围，不声称已完成PackML状态及转换验证。

## 厂商资料入口

- [Sysmac官方规格](https://www.ia.omron.com/products/family/3077/specification.html)：查IEC 61131-10、AutomationML、Axis Settings等具体功能及版本。
- [Sysmac版本更新记录](https://www.ia.omron.com/product/tool/454/sysmac-studio/e1_doc.html)：核对目标版本差异。

按实际问题查找匹配版本的CPU软件手册、指令手册、Sysmac操作手册和所用库手册，不将此skill当作替代手册。

## 每次交付的程序说明

必须给出：文件与导入入口、导入顺序/重复项处理、变量作用域和属性、硬件映射、项目树、程序段与任务执行顺序、设备FB职责/接口、步序条件、启动停止复位、监视测试步骤、实际验证级别。已有模板还应列复用对象、扩展位置和差异；原有第三方/保护代码不随公开交付发布。
