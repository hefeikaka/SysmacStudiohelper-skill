# 从协议文档扩展既有通信工程

用于报文字段表、PPT、采集需求与既有 PLC 通信模板组合的任务。

- 先建立现有库的接口档案，再设计适配程序：记录库名称/版本/命名空间、原实例、输入/输出/输入输出类型、触发方式、完成/错误含义、共享缓冲、调用条件及执行顺序。优先复用满足需求的库FB，不因源码受保护而自行重写通信协议。接口可读不代表内部实现已读；未知握手语义需要手册或原生测试确认。
- 区分“采集输入映射”和“通信FB参数映射”。工程值先接到采集接口，采集结果按业务协议编码，再接到库发布FB；若库已提供所需采集/编码功能则直接复用，避免重复封装。存在发布和实际发送两个FB时，必须保留完整调用链，不能把调用发布FB等同于服务器收到。
- 明确库是否随目标工程保留、桥接代码是否包含在主导入文件中、尚需用户插入的位置。禁止把独立桥接文件已生成描述为原工程已集成。新旧逻辑不能重复调用同一有状态实例或同时写同一发送缓冲。
- 用户要求新建工程可导入时，交付应含独立通信调用POU、完整局部/外部/全局声明及任务顺序，不能继续依赖未交付的旧梯形图。先查找真实SLR并核对库身份、版本、命名空间、依赖和接口；本地随工程交付与公开再分发分开处理。SLR引用、程序XML、任务绑定、硬件组态分别说明，不能承诺一个XML自动完成所有步骤。
- 从工程XML提取接口时，以变量自身的Group及调用引脚方向交叉核对。某些格式会把VAR_INPUT、VAR_OUTPUT、VAR_IN_OUT统一放在名为VAR_INPUT的父组下；不能只用父组名称判断方向。

- 先按源文件 SHA-256 缓存提取结果与来源位置。后续读取相关字段和差异；源文件改变后重新提取，不重复把整份工程、库和文档送入上下文。
- 同目录的截图、导出文本、JSON不自动等于当前文件：先核对页数、内容和摘要。预览可能来自旧版本，不以旧预览补写当前需求。
- PPT 同时读取正文表格和备注。备注可能含断电保持、无效值、分包边界等约束，也可能过期；将它与可见正文对照，冲突写入决策记录，不能无声地选一个版本。
- Windows Python 的标准输出也需明确 UTF-8；第三方脚本如果默认read_text()，同时使用Python的UTF-8模式（`-X utf8`或`PYTHONUTF8=1`）。仅设置PYTHONIOENCODING不能修复文件默认GBK解码。结构化结果优先直接写 UTF-8 文件。
- 建立机器可读的字段契约：Topic、类型、有无符号、元素数/维度、字节宽度、固定偏移、字节序、总长度、保留区、无效值、时间与编号语义。检查字段不重叠、不留未定义空洞、末端等于报文长度；交叉核对表格与备注中的偏移。
- 时间字段还要定义作用域：是每个包内点号、整段动作的连续采样计数，还是墙上时间。分包不能擅自重置整段计数；时间间隔必须使用采集任务的实际周期，不用网络发送周期代替。业务身份字段要逐项核对接收端的映射及查询键，尤其不能把配方、产品、型号等名称相近的字段自行合并。
- 先检查整个传输链路的最小容量：采集缓冲、序列化数组、发布 FB 形参、库队列、发送指令和接收端。扩大调用方数组不能改变保护库的固定形参。容量不足应报告具体接口，不能擅自截断或改变业务分包格式。
- 调用点显示的数组尺寸可能是开放数组实例化后的尺寸；判断固定容量时继续查库的形参声明或正式接口说明，不能仅根据连接点标签推断库上限。
- 模板中随机数、测试开关和被注释的硬件读取必须分别标识。保留连接/重连/发送框架不等于复用旧报文字段或旧采样语义。
- 按厂商指令的实际字节和字处理规则序列化。Omron W502 的 ToAryByte 先处理低字，Order 控制字内顺序；多字节标量可先以 _LOW_HIGH 转换，再在该标量内部反序。不能反转整个数组。结构体可能含对齐填充，固定协议不直接序列化整个结构体；字符串终止符和预留长度需与线上字节数分开。
- 时间格式需要实测或查证厂商输出。DtToString的日期/时间分隔符和纳秒长度可能不同于线上要求，不只截断字符串就认为格式正确。分别核对时区、分隔符、精度、ASCII字节数。
- Omron W501 §6-3-5规定STRING容量包含末尾NULL。存放23字节时间文本至少声明STRING[24]，29字节原始文本至少STRING[30]；同步结构成员、局部、全局及外部声明，但线上字段仍只编码规定的有效字节，不把NULL新增进协议。第三方解释器/XSD可能不检查该厂商规则，需独立断言。
- 库类型引用区分XML/变量表与内部梯形图标识格式。变量表类型误带内部对象的前导反斜杠可能导致类型无效；按匹配目标版本的官方XML样例使用 `LibraryNamespace\BlockType` 一类的限定类型名，不能直接照搬内部对象的绝对路径前缀。用真实SLR、目标编译器继续确认解析结果。
- 依赖库版本表中的CPU固件要求与开发软件版本分开检查。发现同号版本时也不能互相替代；可选适配器单独导出，避免因新增库使原模板全部无法编译。
- 生成导入包前还要查“导入入口”本身对目标单元版本的要求。W504 §8-21列有IEC 61131-10 XML的CPU门槛（如NJ需≥1.19）；旧工程即使由新版Sysmac打开，菜单仍可能不可用。XML通过XSD不能证明目标工程允许导入。若菜单灰色，先核对目标单元版本和当前状态，不让用户把XML改走ST文件导入入口。
- 用独立标准实现生成黄金字节，至少涵盖有符号负数、32/64 位不对称数值、REAL、小数、字符串、数组边界和无效值。区分“模型验证”“源码解释执行”“厂商指令原生执行”。
- 设每包容量为 N，曲线验证单点、N−1、N、N+1、2N、整包加尾包及序号上限；末点标志的数量和位置必须符合实际协议。未结束的整包可保留至下一采样/结束事件再定性，不追加虚假的真实采样点。
- 采集不得因网络忙而默默放慢却仍填写旧采样间隔。缓冲满时给出可见诊断、丢失计数及恢复方式。区分本地排队成功、socket 发送完成、MQTT 确认和业务接收，不能把发布入队 Done 称为服务器确认。
- 周期统计先纳入边界结束事件，再锁定快照；未结束动作跨窗保留计时。重发只能读取已锁定副本。计数溢出、单次时长无效、无传感器与真实零值分别处理。
- 监测程序只观察现有命令/反馈，不能因为检测功能而新增机械动作。与工艺控制共用的变量列明读取者/写入者。
- 参数未知的硬件适配层或文档未定义的报文列为待接入项；不可用永久成功、全零反馈或猜测接口掩盖缺口。

项目数据、地址、点表、原生工程和业务字段契约保留在项目交付目录；skill 仅保存通用规则与可复用检查器。

## 多轴触发与正常收尾

先从实际协议和工艺定义各路触发方式：电平、边沿、开始/完成命令等不自动等价，也不要求所有项目提供相同模式。多路设备分别持有采集状态，不因使用数组就共享启动或结束条件。

明确区分停止新增采样、正常结束并排空、暂停传输和复位丢弃。结束字段的名称、值、作用于点还是包，以及结束扫描是否采样，均来自项目契约；不得从示例推导固定字段或数值。若约定正常结束后继续排空，则尾包及已排队数据不能因触发撤销而清空，通信调用仍需维持。

测试覆盖设备错开启动、不同触发方式、部分尾包、整包边界、前包未确认时的结束、有限缓存、过早重启和断网。每包包含结束字段不意味着每包都是整段末包。将协议未定义的情况记录为待确认，不以某次工程约定填充所有项目。
