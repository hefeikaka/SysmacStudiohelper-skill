# 版本兼容与通信实测

用于目标控制器版本不明、开放数组不可用，或需要把 PLC 报文发到电脑 Broker 的任务。

## 数组能力按目标 CPU 决定

IDE 能编辑 `ARRAY[*] OF T`，不代表目标 CPU Unit Version 支持。先记录实际 CPU 完整型号、CPU Unit Version、工程目标版本和 Sysmac 版本；缺少任一项时，不将开放数组作为已兼容功能交付。

- 若目标版本确认支持开放数组，开放数组只能用于允许的 `VAR_IN_OUT` 接口；检查每个关联数组的下界、上界和长度。
- 若目标版本不支持或未确认，采用固定数组。调用方、数据类型、FB 引脚和循环索引必须使用完全相同的范围，例如都为 `ARRAY[0..31]`；`ARRAY[1..32]` 与它不是同一种类型。
- 固定容量是项目参数。设置 `AxisCount` 限制已启用元素，不可将它解释成数组会动态扩容。原始环形缓冲、协议帧数组和轴通道数组可能有不同容量，逐项保留其用途和范围。
- 不为兼容旧版本而静默截断或伪造系统轴变量；超容量需诊断并停止该次处理。删除开放数组和边界查询后，仍要在目标 Sysmac 原生编译。

## 用结构体减少 FB 引脚

同一责任边界内、生命周期相同的一组数据可合为具名结构体引脚，例如配置、回放数据、通信数据和诊断结果。结构体不是“把整个项目全局变量塞进一个 Context”的理由。

- 结构按读写者和更新顺序划分；写清每个成员的唯一写入者、只读约定和跨任务归属。
- FB 实例队列、边沿记忆、连接状态等实例私有状态继续留在 FB 内部。
- 调用方通过结构体引脚显式连接项目数据；FB 正文不直接引用项目全局名称。
- 数据量较大的结构使用引用接口时，说明其不是原子快照。跨任务只交接经设计的缓冲、索引或握手，不以“全局变量都能读”代替一致性设计。

## 计时与通信状态的回归边界

采集端使用固定宽度无符号计数器作为时间基准时，回绕差值要按该类型的真实最大值计算；另一个统计计数器的饱和值应单独核对，不把两类上限混用。回归用例至少覆盖回绕前后仅经过少量时间、刚到等待阈值、超出阈值三种情况，避免错误常量让报文提前成包。

同一发送器混用不同 QoS 或确认策略时，每次创建新发送请求都要显式设置当前报文的 QoS，不能让上一个报文的状态留在变量里。测试应覆盖高 QoS 报文后紧接低 QoS 报文、确认前队首保留、确认后释放及断线重试；若库缓冲格式未知，模拟 PUBACK 只能证明适配逻辑，不能证明目标库实际行为。

## PLC 与电脑 Broker 的验证证据

Broker 在电脑上监听、PLC 显示发送成功、电脑能自测端口，分别都不足以证明 PLC 报文已被订阅者收到。

1. 先记录 PLC IP、电脑实际网卡 IP、端口、认证/TLS、Topic 和库版本；PLC 不能使用 `localhost` 或虚拟网卡地址作为电脑 Broker 地址。
2. 订阅器先启动，再触发 PLC；对于不保留消息的 Broker，后订阅会错过历史报文。
3. 保存订阅端原始负载和接收日志，验证 Topic、长度、字段布局、每轴/每段标识、末尾标记和收尾队列排空。
4. 先以无运动的测试数据验证网络与格式；再接静止实轴核对反馈；最后在已有现场运动保护条件下验证工艺。测试脚本不能发运动命令或自动下载工程。
5. 报告分开写：离线帧解码、Broker 本机监听、Sysmac 编译、PLC 连接、订阅端实收和实际轴验证。任何未执行项保留为未验证。
