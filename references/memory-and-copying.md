# 变量容量与参数复制

用户要求缩小现场附加程序，或发现嵌套数组、FB实例和大输入结构占用较多时使用。

## 先确认到底分配了什么

- 数组下标可能分别代表采样时刻、设备或待发送报文，先分清这几种含义。运行时启用数量变小不等于静态数组或FB实例数量变小。
- 沿变量和实例类型展开大小：全局一次、程序/FB自有变量按实例倍数计算；包含FB数组的父实例尤其要展开。引用形参不再按完整对象算一份，但其引用实现与厂商类型开销仍以原生编译为准。
- 单独列出厂商库缓冲、轴引用类型、程序自有缓冲、临时快照及任务间变量刷新可能产生的副本。源码只看到一个共享变量，不能证明运行时只有一份存储。
- 报告固定宽度数值字段的减少量、BOOL/字符串/日期等容量假设、未知的厂商和对齐开销。源码核算、工程文件压缩大小与Sysmac编译RAM是不同指标，不互相替代。

## 输入与输入输出的选择

大结构/数组从输入输出改成仅输入，可能引入按值参数复制及实例存储；不能因为引脚只读就默认更快、更省。保留合法引用时注明只读约定及唯一写入者。FB正文中的结构赋值、输出赋值和跨任务刷新仍可能复制，引用传递不等于整个调用零复制。

现场比较应记录相同任务设置、数据类型和尺寸、调用次数、内部复制开关、输出校验、平均/最大时间和超限次数；尽量清统计并采用A→B→A重复。只有整体任务计时的差值时，按调用次数分摊只能称估算。应保存原截图、原条件、工程版本/哈希及未验证项。放大数组的压力测试不能直接按字节比例推算生产程序收益，耗时截图也不能证明RAM节省。

具体读数和客户工程放项目证据目录，不装进通用skill，也不把某一项目的引脚方向改成所有FB的硬规定。还须检查引用形参必须合法绑定，未启用设备不被解引用。

## 精简顺序与必须保留的语义

1. 先删经用户确认不需要的分支和状态，同步类型、声明、调用、原生工程及检查；不能只隐藏引脚而留下缓存。
2. 区分逐点反馈与每动作头参数。目标位置/速度/加减速等一般只需在动作开始时锁定，禁止每个采样时刻重复整份配置；异步消费时仍需保留当时值。开始事件可能排队时，用有界事件队列或明确确认的快照，不能拿发送时的最新目标替换旧动作。
3. 删除重复默认配置表；在固定配置生命周期和任务一致性得到确认后，从已有配置读取回退值。不能删除正在编码的冻结源或待确认报文，致使下一包覆盖上一包。
4. 协议常量保留区可由编码器直接生成，不必在每设备的结构化工作帧中存相同常量。线上字段、偏移、总长保持完整，用独立黄金报文验证。
5. 缩小本地字节数组前核对实际协议长度与所有MemCopy/指针式调用。源和目的容量分别检查；厂商固定形参缓冲不可跟着本地队列一起随意缩短。
6. 数值类型尽早压到线上所需精度，但必须先在原生反馈精度下检查有限值和范围。精度损失提示和单位语义分别处理，不伪造比例换算。
7. 调整采样环大小时同步类型、取余、边界、预算、积压显示、暂停与复位清理。保留一格的环实际容量少一；慢/快倍率仅是最小到达量，还需处理延迟余量。容量不能解决长期消费不足。

验证跨任务目标锁存、多个开始事件、事件与采样一一关联、环回绕、满队列不覆盖、多设备独立数据、结束扫描和完整尾包。离线替身、原生编译、实机计时/内存分别报告。优先复用小型辅助块，既不要增加大量重复实例，也不要为少一层封装把大对象搬到按值输入。
