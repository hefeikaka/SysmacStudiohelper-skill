# 采集信号与事件核对

适用于根据现有 Sysmac 工程核对设备采集表、恢复被注释的采集映射，或排查设备计数及动作时间。表格、变量名和截图是线索，先以实际工程的数据类型、程序调用和任务上下文建立证据；不把某个项目的设备编号、结构名、方向或单位套用于其他工程。

## 逐级确认变量和信号意义

- 按“全局变量 → 结构类型 → 每级成员 → 数组范围 → 末端类型”解析完整路径，并检查引用它的 POU 是否具备同名、同类型及匹配属性的外部声明。全局根变量存在不代表每级成员存在；补外部声明也不能修复错误成员路径。先确认是否漏掉中间结构层；找不到成员时列为待确认，不以近似名称猜测设备或新建变量代替。
- 尽可能追踪输入映射、设备 FB 的调用和输出、工艺实际判断及采集使用的位置，区分原始输入、设备处理后的状态、命令、完成反馈和报警。受保护 FB 内部不可读时，不能假设输入与输出永远相同；记录推断及现场需要验证的部分。
- 真空吸附反馈为 FALSE 只说明该反馈不成立，可能是释放、泄漏、传感器状态变化等，不能单凭它证明破真空或释放动作完成。伸出与缩回、吸附与释放是否各有独立反馈，须结合设备工艺、接线、FB语义和采集契约核对；不要把同一个电平直接复制到两个方向并假定均可统计。
- 对照表记录设备标识、目标字段、实际完整路径、变量类型、信号含义、来源与证据、可信状态及待确认项；区分表格行号、设备编号、PLC 数组下标及平台编号，记录从零或从一开始的换算。不能确定的项目保持明确待确认，不伪造映射。

## 动作时间与事件计数

- 时间字段同时核对数组下标表示的方向、源类型和单位、目标字段单位、整数转换的精度、范围及溢出处理。类型转换只改变表示形式，不自动完成秒到毫秒等单位换算。即使类型注释给出了含义，也要检查 FB 和调用方实际使用方式；受保护内部无法确认时保留限制，用现场动作与在线值验证。
- 检查采集器具体按电平、上升沿、下降沿还是命令与反馈配对来计数。同一设备的两个方向若先做 OR 再检测上升沿，A 从 TRUE 切到 FALSE、B 同时变为 TRUE 时，合并信号可能始终为 TRUE，第二个动作不会产生新的上升沿。依据需求评估独立方向边沿或有状态事件方案，测试连续切换、同时为 TRUE、短脉冲、重复信号和复位；先核实原业务语义再修改，不把其中一种算法当普适答案。
- 暂停某项采集时检查对应赋值是否会周期执行、是否存在其他写入者，以及旧状态、缓存和排队数据如何处理；仅把输入置 FALSE 不自动清除历史数据或证明所有任务停采。

## 启用原有注释代码

仅在用户要求或授权的范围解除注释。逐条区分已有真实表达式和未绑定的占位示例；核对声明、成员类型、数组边界、目标下标和实际调度容量。检查同轴多个段是否可能由相同或重叠条件同时触发，以及是否违反现有调度器前提；对无法从工程确认的工艺意图保留原意并标出风险，不擅改条件。

对实际交付副本做静态核对和适用的行为测试，记录检查覆盖范围；受保护 FB、变量运行值、短脉冲及实际工艺仍可能需要 Sysmac 原生编译、在线监视和现场验证。路径可解析不代表计数准确，编译通过也不证明信号语义正确。
