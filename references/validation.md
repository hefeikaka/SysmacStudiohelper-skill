# 验证与能力证据

## 完成级别

每阶段分别记录通过、失败、部分完成、未执行或不适用，并给出实际对象和证据。

|阶段|最低证据|不能由此推断|
|---|---|---|
|文件识别|签名、可读取目录或清单|所有正文可读|
|结构解析|实体关联、代码/变量来源、未解析对象|全部执行语义已还原|
|静态检查|检查范围、诊断及源文件位置|工艺已正确运行|
|文件生成|转换记录、实际输出、对象及引用核对|目标软件能导入|
|Sysmac导入|目标软件版本、导入结果、对象核对|编译通过|
|Sysmac编译|目标控制器/版本及编译结果|仿真或机械行为通过|
|仿真|运行环境、输入序列、预期与实际结果|现场I/O及机械行为一致|
|实机验证|实际设备、条件、测试及观察记录|所有未测工况正确|
|原生工程交付|副本保存、关闭重开、结构核对与所声明编译结果|其他软件版本自动兼容|

同一文件、同一版本和同一目标的证据才能直接支持对应结论。旧缓存中的编译结果不能当作本次修改的编译结果。

## 自验证设计

- 优先验证交付的实际源码。独立Python行为模型可以辅助比较，但不能把模型通过当成PLC源码通过。
- 解释器执行和Sysmac执行分别记录；说明时钟、任务调度、I/O刷新及厂商指令覆盖差异。
- 测试应覆盖当前工艺的正常路径、边界、互锁、超时、故障及恢复。不强制沿用固定用例数量或某个演示案例的断言。
- 对梯形图/Inline ST，检查导通条件、串并联、上下梯级顺序、置位复位竞争、边沿与有状态FB。仅验证ST框正文不足以验证其所在程序。
- 对重构或语言转换，对比修改前后的输入轨迹与输出/状态；刻意改变的行为单独说明。
- 汇报场景与覆盖范围。大量重复断言不等于独立场景，也不等于形式化正确性证明。
- 注入轴到位/传感器反馈来执行工艺 ST，只能证明对应顺序逻辑，不证明厂商运动指令、加减速曲线、EtherCAT 或机械配合已验证。
- XML 语法、官方 XSD、链接完整性、目标软件实际导入分别报告。若校验器不兼容官方 XSD，应优先用兼容的校验实现读取原始 XSD，记录差异，不静默修改厂商约束后宣称原始格式通过。
- 生成有序 XML 时，新增节点须遵循对应类型的子元素顺序，不能只使用末尾追加。AutomationML 的接口、子设备、角色和连接需要分别定位；端点全部存在不代表 CAEX 结构合法。以目标软件的导入错误更新验证记录，保留失败版本证据，修复后检查同组顺序及连接属性不变。

## 导出一致性

核对生成文件中的POU、变量作用域和类型、实例引用、依赖库及源代码正文。必要时采用摘要关联测试版本与交付版本。

解释器、转换器或静态工具失败时，先判断是源码错误还是工具不支持。不能静默删掉不支持的逻辑来取得通过；使用替代实现应说明行为影响并重新验证相关场景。

新修改、失败或未解决风险才触发相关重测；普通说明文字修改不必重跑不受影响的全部测试。

## 用户报告

先说实际读到或完成了什么，再说明影响后续工作的限制。用具体语言：

- “已解析该程序段的触点和ST框关联，尚未还原全部连接图。”
- “已生成FB定义和XML，尚未在目标Sysmac导入。”
- “实际ST在解释器通过指定场景，Sysmac编译未执行。”

只有已验证的能力才能用“已完成”描述。缺少工具或接口时可继续独立工作并提供可执行的下一步，不为未经验证的全自动流程作承诺。

- 轴单位或比例改变时，检查相关速度、加减速、点动、定位范围及原点参数的物理单位和内部换算范围；不可假设目标工程的默认数值会自动协调。XSD 中的字符串数值字段还需做数值范围及指令参数与轴上限的一致性检查。
- 替换生成 POU 的正文时同步核对新增符号的声明。轴的全局 AT 绑定和 POU 的 ExternalVars 是两层不同依赖；目标已经有轴变量仍可能因 POU 未声明外部引用而报未定义。此类错误先检查声明，不能只换成另一种轴名。
- 外部声明必须匹配其全局变量的类型及常量等属性。XML 省略属性会使用格式默认值，不等于继承目标全局属性；出现属性不匹配时优先同步外部声明，不更改已有系统绑定变量来适应生成文件。不要把单个轴的属性设定推广给所有变量。
